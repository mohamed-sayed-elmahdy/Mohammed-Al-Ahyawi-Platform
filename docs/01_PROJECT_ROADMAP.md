# Development Workflow

The project follow the same workflow used by professional software companies.

## Phase 1 — Project Architecture

No coding at this stage.

Everything should be planned first.

Development order:

1. Vision
2. Brand identity
3. Sitemap
4. Product Requirements Document
5. User Flow
6. Wireframe
7. High Fidelity Design
8. Design System
9. Database Design
10. API Planning
11. Folder Structure
12. Development
13. Testing
14. Deployment

---

- Contact

# Phase 4 — Wireframe

Example:

- Navbar
- Hero
- Featured Content
- Statistics
- Latest Reviews
- Stories
- Countries
- Footer

# Phase 6 — Design System

Before writing any code, define the complete design system.

It should include:

- Colors
- Typography
- Spacing
- Border Radius
- Shadows
- Buttons
- Cards
- Inputs
- Icons
- Animations

This ensures consistency throughout the entire application.

---

# Phase 7 — Database Planning

Plan the database before implementation.

Expected collections:

- Users
- Reviews
- Stories
- Countries
- Cities
- Places
- Categories
- Visit Requests
- Articles

---

# Phase 8 — ER Diagram

Design the Entity Relationship Diagram (ERD).

This will define how every entity in the database is connected.

---

# Phase 9 — API Planning

Plan every endpoint before development.

Examples:

- GET Reviews
- GET Stories
- POST Visit Request
- PATCH Review
- DELETE Story

---

# Phase 10 — Folder Structure

Design the project structure before opening the editor.

A clean architecture will make the project easier to scale and maintain.

---

# Phase 11 — Development

Only after all planning phases are complete should development begin.

At this point, VS Code can finally be opened.

# Product Requirements Document (PRD)

A dedicated Product Requirements Document should be created.

Suggested filename:

`PRODUCT_REQUIREMENTS_DOCUMENT.md`

This document will become the project's primary source of truth.

It should include:

- Project Vision
- Target Audience
- Goals
- User Personas
- Features
- Pages
- Database
- API
- Roadmap
- Future Plans
- Design Language
- Tech Stack

Every future project change should be documented here.

- GitHub
